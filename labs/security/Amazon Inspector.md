# Amazon Inspector

## Overview

This lab focused on activating and using **Amazon Inspector** to continuously scan AWS resources for software vulnerabilities. The primary objective was to activate Inspector, review vulnerability findings affecting AWS Lambda functions, investigate a vulnerability using the National Vulnerability Database (NVD), remediate the vulnerable package, and verify that the vulnerability finding had been successfully closed.

The lab demonstrated how Amazon Inspector can continuously monitor supported AWS resources, identify vulnerable software packages, provide detailed vulnerability information, and support the remediation and verification process.

---

## Task 1: Activate Amazon Inspector

Activated Amazon Inspector to enable continuous vulnerability scanning for the AWS environment.

Key activities completed:

* Opened **Amazon Inspector** from the AWS Management Console.
* Activated Inspector for the AWS account.
* Confirmed that Inspector was successfully activated.
* Waited for the initial Inspector scan to begin.
* Monitored the Inspector dashboard while the initial scan was running.
* Verified the **Lambda functions** environment coverage reached **100%**.
* Reviewed the Inspector dashboard and activation status for AWS Lambda.

Amazon Inspector provides continuous vulnerability scanning for supported AWS resources, including **Amazon EC2, Amazon ECR, and AWS Lambda**.

Skills demonstrated:

* Amazon Inspector activation
* Vulnerability scanning
* AWS Lambda security monitoring
* Inspector dashboard navigation
* Resource coverage monitoring
* Continuous security assessment

## Task 2: Review Amazon Inspector Findings

Reviewed the vulnerability findings generated by Amazon Inspector for the Lambda functions.

Key activities completed:

* Opened **Findings → All findings**.
* Reviewed the three vulnerability findings displayed for the Lambda functions.
* Examined the **Severity** of each finding.
* Reviewed the **Impacted resource** associated with each vulnerability.
* Examined the **Title** of each finding to understand the vulnerability.
* Selected the `CVE-2023-32681 - requests` finding.
* Opened the vulnerability information pane.
* Reviewed the **Vulnerability details** section.
* Followed the external link next to the **Vulnerability ID**.
* Reviewed the vulnerability information provided by the **National Vulnerability Database (NVD)**.
* Examined the **Remediation** section of the Inspector finding.
* Identified the `requests` Python package as vulnerable and outdated.

The vulnerability finding demonstrated how Amazon Inspector provides information about the affected resource, vulnerability identifier, severity, and recommended remediation.

Skills demonstrated:

* Vulnerability identification
* Amazon Inspector findings
* CVE analysis
* Vulnerability severity assessment
* NVD research
* Lambda dependency analysis
* Vulnerability remediation planning
* Security findings interpretation

## Task 3: Remediate Lambda Package Vulnerabilities

Updated the affected Lambda function to remediate the vulnerable Python package identified by Amazon Inspector.

Key activities completed:

* Opened **AWS Lambda** from the AWS Management Console.
* Selected the `get-request` Lambda function.
* Opened the Lambda function code editor.
* Located the `requirements.txt` file.
* Identified the vulnerable package version: `requests==2.20.0`.
* Removed the version number and equal signs.
* Updated the dependency to: `requests`.
* Deployed the updated Lambda function.
* Confirmed that the Lambda function was successfully updated.
* Recognized that the new deployment would trigger Amazon Inspector to initiate a new scan of the function.

The `requirements.txt` file defines the Python packages required by the Lambda function. Removing the pinned version allowed the deployment process to install the current version of the package.

Skills demonstrated:

* AWS Lambda management
* Python package management
* Dependency management
* `requirements.txt`
* Vulnerability remediation
* Lambda function deployment
* Software security updates

## Task 4: Verify Vulnerability Remediation

Returned to Amazon Inspector to verify that the vulnerability had been successfully remediated.

Key activities completed:

* Returned to **Amazon Inspector**.
* Opened **Findings → All findings**.
* Changed the finding status from **Active** to **Closed**.
* Located the `CVE-2023-32681 - requests` finding under the closed findings.
* Confirmed that the vulnerability finding had been closed.
* Opened **Resources coverage → Lambda functions**.
* Reviewed the Lambda function scanning information.
* Checked the **Last scanned** timestamp.
* Confirmed that the Lambda function had been scanned again following the updated deployment.

The closed finding confirmed that the vulnerable `requests` package had been successfully remediated.

Skills demonstrated:

* Vulnerability remediation verification
* Amazon Inspector findings management
* Closed finding analysis
* Lambda resource scanning
* Security validation
* Continuous vulnerability monitoring
* Remediation verification
